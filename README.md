# FLR獲得金額算出アプリ

Flare (FLR) のウォレットアドレスから、**デリゲート／ステーキング報酬**と**ガス代**を
自動収集し、日本の確定申告に必要な情報とおおよその税額を算出するツールです。

**2つの版があり、集計ロジックは完全に共通です**（`shared/` に置いてあり、必ず同じ結果になります）。

| | ローカルWebアプリ版 | 静的サイト版 |
|---|---|---|
| 用途 | 自分で使う | 他の人にも使ってもらう |
| 必要なもの | Node.js | ブラウザだけ |
| 保存先 | SQLite (`data/`) | ブラウザのlocalStorage |
| 公開 | しない | GitHub Pages 等に無料で置ける |
| 再スキャン | 約3秒（差分取得） | 約2秒（差分取得） |

## できること

| 機能 | 内容 |
|---|---|
| 報酬の自動収集 | FTSOデリゲート報酬、ステーキング報酬、FlareDrop、RNat報酬、データ提供者手数料 |
| ガス代の集計 | ウォレットが送信した全トランザクションの手数料 |
| 円換算 | 受取日ごとの時価（FLR/USD × USD/JPY）で自動評価 |
| 期間指定 | 任意の期間、または年単位のプリセット |
| 複数ウォレット管理 | アドレスを保存し、複数を選んで合算集計 |
| 税金の試算 | 雑所得としての所得税・復興特別所得税・住民税の概算 |
| エクスポート | Excel (.xlsx) 7シート構成 / CSV（Googleスプレッドシートでも開けます） |
| 確定申告 記入ガイド | 国税庁「暗号資産の計算書」（総平均法用・移動平均法用）に記入済みのExcelを生成 |

## 1. ローカルWebアプリ版の使い方

必要なのは **Node.js 22.5 以降**（`node:sqlite` を使うため）だけです。

```bash
npm install
```

```bash
npm start
```

ブラウザで **http://localhost:3000** を開きます。

1. ウォレットのアドレス（`0x…`）を登録
2. 期間を選ぶ（「全期間」ボタンで全履歴）
3. 「集計する」を押す
4. 他の所得を入力すると税額が試算される
5. 「Excel でダウンロード」で出力

> 初回のスキャンは全履歴を走査するため **1〜3分** かかります。結果はキャッシュされるので2回目以降は数秒です。

## 2. 静的サイト版の公開手順（無料）

サーバー不要で、ブラウザだけで動きます。**利用者のアドレスがどこかのサーバーに送られることはありません。**

### 動作確認

```bash
npm run build
```

```bash
npm run serve:static
```

**http://localhost:4000** で確認できます。

### GitHub Pages で公開する

1. このリポジトリを GitHub に push する
2. リポジトリの **Settings → Pages → Source** を「**GitHub Actions**」にする
3. **Settings → Actions → General → Workflow permissions** を「**Read and write permissions**」にする

これだけで `https://<ユーザー名>.github.io/<リポジトリ名>/` に公開されます。
`.github/workflows/deploy.yml` が以下を自動で行います。

- push のたびに再デプロイ
- **毎週月曜に価格データを自動更新**してコミット

Cloudflare Pages / Netlify などに置く場合は、`npm run build` を実行して
`static/` フォルダの中身をそのままアップロードするだけです。

### なぜ無料で運用できるのか

- **Flare Explorer (Blockscout) が CORS を開放していてレート制限も無い**ため、ブラウザから直接呼べる
  （`x-ratelimit-limit: -1` を実測で確認）
- そのため各利用者が自分の回線からアクセスする形になり、**負荷が1箇所に集中しない**
- 価格データは 20KB の JSON をリポジトリに同梱しているので、価格APIへの依存も最小限
- サーバーが存在しないので、ホスティング費用も、あなたが個人情報を預かる責任も発生しない

### 差分取得のしくみ

ブロックチェーンは追記専用で、確定したブロックの中身は二度と変わりません。
そこで「どこまで読んだか」をブロック番号で記録しておき、2回目以降は**その続きだけ**を取得します。

```
初回:   [========== ブロック0 〜 最新 ==========]   1〜3分
2回目:  [ 保存済み（読まない） ][重ねて読む][新規]   2〜3秒
                                ↑ここから読み直す
```

実測で **78秒 → 2.4秒**（約30倍）になります。

正しさのために次の工夫をしています。

- **重ねて読む幅（約20万ブロック＝2〜3日ぶん）** … チェーンの再編成(reorg)や、
  Explorer の索引付けが最新に追いついていない場合に備え、前回の終点より手前から読み直します
- **「消してから入れ直す」** … 読み直した範囲は、キャッシュ側の該当ぶんを一度削除してから
  新しい結果を入れます。単に重複を除くだけだと、再編成で無効になったログが残り続けてしまうためです
- **失敗したら位置を進めない** … 取得に失敗したコントラクトは読み取り位置を据え置き、
  次回あらためて同じ範囲を取り直します（取りこぼしを作らないため）
- **形式が変わったら作り直す** … キャッシュにバージョンを持たせ、集計ロジックを変えた場合は
  古いキャッシュを読み捨てて全期間を取り直します

有効期限は設けていません。毎回差分を取りに行くので、**内容は常に最新**です。
全部を取り直したい場合は「全期間を取り直す」にチェックを入れてください。

検証は `npm run verify:incremental` で行えます。全期間取得の結果と差分取得の結果が
完全一致すること、再編成を模擬しても壊れないことを確認しています。

### 報酬の取得方法について

報酬の検出には**イベントログ**（`RewardClaimed` など）を使っています。

これは重要な設計判断です。「ウォレットに届いた FLR の送金を数える」という素朴な方法では、
**報酬を WNat（ラップFLR）で受け取った場合に収入を丸ごと取りこぼします**。
その場合、FLR は RewardManager から WNat コントラクトへ動くだけで、ウォレット自体には届かないためです。
イベントログは受取方法に関係なく必ず記録されるため、こちらを正としています。

対象コントラクトのアドレスは、実行時に **FlareContractRegistry**（オンチェーン）から取得するので、
コントラクトが更新されても自動的に追随します。

### 円換算の方法

```
評価額(円) = 数量(FLR) × その日の FLR/USD 終値 × その日の USD/JPY 終値
```

- 日付は**日本時間(JST)の暦日**で判定します（日本の税務は暦年基準のため）
- 為替は土日祝に値がないため、**直近営業日のレートを繰り越し**ます（該当件数は画面に表示されます）
- CoinGecko の無料APIは過去365日しか遡れないため、全期間を無料で取得できる Yahoo Finance を使っています
  （静的サイト版は Yahoo が CORS 非対応のため、同梱JSON + CoinGecko/frankfurter で代替）

### 税金の計算について

日本では、暗号資産の報酬は原則として**雑所得（総合課税）**となり、
給与など他の所得と合算して累進課税されます。報酬は**受け取った時点の時価**で収入計上します。

このアプリは「FLR報酬によって税金がいくら増えるか」を、
**FLR報酬ありの税額 − FLR報酬なしの税額**として算出します。
これにより、累進課税で税率が変わる影響も正しく反映されます。

使用している制度（2026年8月時点）:

- 所得税の速算表（国税庁 No.2260）
- 基礎控除（国税庁 No.1199 / 令和7年度税制改正。令和7・8年分の上乗せ特例に対応）
- 復興特別所得税 2.1%
- 住民税 所得割 10%（均等割は含みません）

> ⚠️ **この試算は概算です。** 実際の納税額は他の所得・各種控除・お住まいの自治体によって変わります。
> ガス代を必要経費に算入できるかは、その支出が報酬獲得に直接必要だったかで判断が分かれます。
> 確定申告の際は必ず税理士または税務署にご確認ください。

### 確定申告 記入ガイド（暗号資産の計算書）について

暗号資産取引がある場合、確定申告では国税庁の
[暗号資産の計算書（総平均法用）](https://www.nta.go.jp/taxes/shiraberu/shinkoku/yoshiki/02/xlsx/002.xlsx) /
[（移動平均法用）](https://www.nta.go.jp/taxes/shiraberu/shinkoku/yoshiki/02/xlsx/001.xlsx)
の作成・保存が求められています。「４　税金の試算」の下に「５　確定申告 記入ガイド」が表示され、
このアプリが把握しているデータを国税庁の公式様式にそのまま反映した Excel をダウンロードできます
（様式は `assets/nta-templates/` に同梱しており、外部サイトへの通信は発生しません）。

このアプリのデータだけで計算書に記入する場合の考え方:

- **報酬の受取り** → 受取り時点の時価で暗号資産を「購入等」したものとして計上します。
  この時価は既に「４　税金の試算」の雑所得として別途計上済みで、二重計上ではありません。
  ここではその後の売却（＝ガス代支払い）に使う取得価額（コストベース）を積み上げているだけです。
- **ガス代の支払い** → Flareネットワークではガス代を FLR 自体で支払うため、暗号資産の
  「売却等」（讓渡）として扱われます。取得時からの平均取得単価との差額が、追加の所得
  （またはマイナス）になります。

対応している計算方法は2つです。

| 方式 | 精度 | 備考 |
|---|---|---|
| 総平均法（既定） | 年間の合計だけで決まるため、取引順序に関係なく厳密に一致します | 届出をしていなければ法定の方法 |
| 移動平均法 | 参考値（近似計算） | 取引のたびに逐次平均を再計算する方式のため、月単位に集計して近似しています |

> ⚠️ このアプリが把握しているのはオンチェーンの報酬とガス代だけです。取引所での売買・交換や、
> 年始時点で既に保有していた残高（前年から繰り越した数量・金額）は含まれません。該当する場合は
> 「年始残高」欄に手入力してください。ダウンロードした Excel は「氏名」欄が空欄のため、
> ご自身で入力する必要があります。あくまで記入補助であり、最終判断はご自身の責任で行ってください。

## 検証

```bash
npm run verify:all
```

2種類の検証があります。

**`npm run verify`（37項目）**
静的サイト版は軽量化のため ethers を積んでいません（イベントの topic ハッシュは埋め込み、
ABI 復号は自前実装）。**ethers を正解として実チェーンのデータで突き合わせ**、その手抜きが
正しいことを確認します。あわせて税額計算を国税庁の速算表と照合します。

**`npm run verify:incremental`（13項目）**
差分取得が「速いが間違っている」状態になっていないかを確認します。
全期間取得と差分取得の結果が完全一致すること、読み取り位置を巻き戻しても取りこぼさないこと、
再編成を模擬して不正なログを混ぜても除去されることなどを検証します。

## Excel の出力内容

| シート | 内容 |
|---|---|
| サマリー | 期間・合計・税額の概算 |
| 報酬明細 | 1件ごとの日時・種別・数量・レート・評価額・Txハッシュ |
| ガス代明細 | 1件ごとの日時・メソッド・手数料・評価額 |
| 種別集計 | デリゲート／ステーキング／FlareDrop などの内訳 |
| 月別集計 | 月ごとの報酬・ガス代・差引 |
| 年別集計 | 年ごとの雑所得の金額（確定申告用） |
| 注意事項 | 計算の前提と警告 |

複数ウォレットを選択した場合は「ウォレット別」シートも追加されます。

## データの保存先

- ローカルWebアプリ版: `data/flr-tax.db`（SQLite）。`.gitignore` 済みなので公開されません
- 静的サイト版: 利用者のブラウザの localStorage のみ

どちらも外部にウォレット情報が送信されることはありません（ブロックチェーンの公開データを読むだけです）。
リセットしたい場合は `data/` フォルダを削除、または静的サイト版ではブラウザのサイトデータを消してください。
